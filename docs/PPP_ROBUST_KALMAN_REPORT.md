## 2. C：一次验前Huber权重EKF

新增显式 `RTK_PPP_BASELINE=C`，沿用A的函数模型、固定Q、基础R0、数值保护和CORRECTED周跳弧段。B的历史抗差、平滑、持续质量和虚拟大气约束不进入C。D仍不能选择。默认保持B；A/B没有因此改变运行行为。

对每次编辑试算，在形成完整的验前 `v/H/R` 后、调用原 `filter()` 前，对真实GNSS码/相位行计算：

```text
Sii = h_i P^- h_i^T + Rii
u_i = v_i / sqrt(Sii)
w_i = 1                    , |u_i| <= 1.5
w_i = 1.5 / |u_i|          , |u_i| > 1.5
R_eff,ii = Rii / w_i
```

`H`是RTKLIB实际的列主序 `nx×nv`，第i条观测是其一列；`P^-` 是本次 `filter()` 前同一个预测副本。Huber的截断影响函数是方法来源；这里是**一次验前权重更新**，不宣称实现了完整迭代M估计。[Huber原论文](https://projecteuclid.org/journals/annals-of-mathematical-statistics/volume-35/issue-1/Robust-Estimation-of-a-Location-Parameter/10.1214/aoms/1177703732.full)。截止值1.5为本次固定、未用真值调优的实验参数；它不是从当前手机数据证明的最优值。

仅GNSS_CODE和GNSS_PHASE可加权；IONO/TROP/其他虚拟约束不进入权重函数。每个观测行只在当前历元使用自己的u，不按信号维护跨历元系数，不进行eta或Q更新，也没有新增拒绝门限。所有候选新R先校验，任一非法则整次试算失败且不修改该R；`filter()`后仍须通过Phase 1后验提交门。验后编辑从同一预测重试，不重复提交观测。

`$PPP_HUBER`日志记录GNSS时刻、trial、row、卫星、实际signal、码/相位、原u、权重、加权前/后的R。C的`$PPP_R_PRE_HUBER`只表示`ppp_res()`阶段的方差；最终进入`filter()`的方差应读`$PPP_HUBER.R_eff`或新增创新CSV的`obs_var`。A/B的原`$PPP_R`日志格式保持不变。C日志与CSV逐行对照已通过。

TXT C的562个降权中码418、相位144；最小权重0.27989，最大|u|=5.35926。C与A的共同600历元均有效，Q/ns未变，但最大三维坐标差7.36771m；这只是算法输出差异，**没有真值精度结论**。同输入C重复两次输出及状态文件一致。打开创新CSV后，42043条真实观测的记录R与`$PPP_HUBER.R_eff`逐行吻合，诊断开/关的坐标和状态相同。

TXT中C的reject为102，A为0：C没有添加新的拒绝规则，但Huber改变后验，既有8σ验后门控会对变化后的残差作出不同决定。C的结果因此同时包含权重与既有门控的联动效应；不能把全部坐标变化归因于Huber权重本身。后续若要单独估计权重效应，应给A/C设置相同且明确的拒绝策略，另做成对实验，不能悄悄更改本次A基线。

RINEX C的最大|u|为1.05371，低于1.5，因此全部权重为1，C与A的数值输出和状态文件完全一致。这是该输入的实测现象，不证明抗差滤波在所有RINEX场景都无作用，也不能为产生变化而调低阈值。
